# 21604/AI应用与智能体开发

获课：itazs.fun/21604/AI应用与智能体开发

AI应用与智能体开发最容易走偏的一步，是在起步阶段就把“应用开发”和“算法研究”混为一谈。力扣社区一份高赞路线给出的判断颇为清醒：AI智能应用开发不等于算法炼丹，核心是“用模型+工程落地”。这个定位一旦模糊，学习者就会滑向啃PyTorch和数学推导的漫长歧路，而市场真正缺的，是能把大模型接进业务系统、让它可靠跑完一件事的人。

路径分化：Java与Python是两套打法，不是同一件事

选择哪条技术栈，取决于你已有的工程底子与目标岗位。如果已有Java/Spring基础，优势在于国内大量AI中台与业务系统的底座仍是Java生态，岗位缺口在“懂Java工程+会用大模型”的复合型人才。务实路线是：先跑通Spring Boot的CRUD项目，再用Spring AI或LangChain4j完成三个里程碑——带Redis会话的对话Bot、能调外部工具的助手、简易RAG问答。向量库从PGVector起步，避免在Milvus的部署上消耗开局耐心。

如果从零开始或偏Python背景，路径则围绕LangChain/LangGraph展开。开源教程《AI智能体实战速成指南》的定位很明确：聚焦Python生态，直接对齐Agent工程最常用的技术路线。其项目设计值得参考：电商问数用NL2SQL加LangGraph串起意图解析与多轮修正，深度研搜用DeepAgents练多智能体协作。两条路径的共同底线是：不做完一个能跑通、能演示的项目，概念学得再多都不算数。

企业级要求的真正门槛：可观测性，而非框架熟练度

从招聘要求反推能力缺口，最能说明问题。阿里云AI Agent全栈开发工程师的岗位描述中，排在前列的不是“熟悉LangChain”，而是“构建评估系统和自动化评估流程，建立Agent性能、质量和成本的可观测体系”。神州数码的Agent工程师岗位同样将“RAG增强、Function Calling集成、Agent编排框架开发”与“分布式任务调度及常见中间件”并列。这些要求的共同指向是：Agent开发的上半场是提示词与工具调用，下半场是评估、监控、降级与成本控制。LangGraph之所以被生产环境偏好，恰恰因为它把智能体行为建模为显式状态图，节点与条件分支让长流程任务可恢复、可观测，而非一个黑盒式的对话循环。

收束：先做窄，再做深

AI应用与智能体开发的入门路径可以归结为一句克制的话：先在一个垂直场景里把“感知—决策—执行—观测”的完整链路跑通，再谈扩展。对话Bot加工具调用加RAG问答，三个项目串起来就是一个可讲清楚设计思路的简历素材。框架会迭代，模型会换代，但让一个会思考的系统不闯祸、不失控、不烧钱的本事，才是这个方向真正的护城河。
